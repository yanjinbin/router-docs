ImmortalWrt · R5C · 25.12.0 · Nikki / Mihomo

Nikki 透明代理
两种 DNS 分流策略对比

方案一：纯国内 DNS，无 nameserver-policy，所有域名走国内 DoH，极简低噪。
方案二：国内 + GFW 分流，geosite:gfw 走代理 DoH + ECS，兜底保留境外 1.1.1.1。

ℹ️
运行环境：ImmortalWrt 25.12.0 · NanoPi R5C · Nikki（Mihomo 内核）· TUN stack=mixed · nftables 透明代理 · fake-ip 198.18.0.1/16。两份配置的 sniffer、fake-ip-filter、tun、profile 完全相同，差异仅在 DNS 段。
方案对比总览 核心差异
方案一 · 纯国内 DNS
无 nameserver-policy，全部域名兜底走国内 DoH；find-process-mode 显式关闭
nameserver-policy 无（不配置）
nameserver（兜底） 223.5.5.5 / doh.pub（纯国内）

境外域名解析 同样走国内 DoH，依赖 sniffer 还原真实域名后走代理
方案二 · 国内 + GFW 分流
有 nameserver-policy，国内域名走国内 DoH，gfw 域名走代理 DoH + ECS，兜底含 1.1.1.1
nameserver-policy geosite:cn,private → 国内 DoH
geosite:gfw → 8.8.8.8#RULES+ECS / 1.1.1.1
nameserver（兜底） 223.5.5.5 / doh.pub / 1.1.1.1
find-process-mode 注释掉（使用默认值）
境外域名解析 gfw 列表走代理 DoH，ECS 返回大陆友好 IP
方案一 · DNS 解析路径（无 policy，全走国内）
任意域名查询 → nameserver 兜底 → 223.5.5.5 / doh.pub · 国内域名返真实 IP；境外域名返 fake-ip，sniffer 后走代理
方案二 · DNS 解析路径（有 policy 分流）
域名查询 → geosite:cn / private → 223.5.5.5 / doh.pub 真实 IP，直连最优 CDN
域名查询 → geosite:gfw → 8.8.8.8#RULES&ecs=223.5.5.0/24 / 1.1.1.1 代理 DoH，ECS 返回大陆友好 IP
域名查询 → 未命中 policy → 223.5.5.5 / doh.pub / 1.1.1.1（兜底）

关键差异详解 3 处变化
⚠️
两方案仅 DNS 段不同，其余 TUN、sniffer、profile、fake-ip-filter 完全相同，蓝色高亮为方案一独有，绿色高亮为方案二独有。
① find-process-mode
方案一 V1
find-process-mode: off   # 显式关闭
方案二 V2
# find-process-mode: off  # 注释，用默认值
方案一显式关闭进程匹配，减少 CPU 开销，路由器上无 GUI 进程需要区分，关掉更省资源。
② nameserver-policy（核心差异）
方案一 V1
# 无 nameserver-policy
# 所有域名走 nameserver 兜底
nameserver:
  - https://223.5.5.5/dns-query
  - https://doh.pub/dns-query
# fallback 已删，全国内无需双查
方案二 V2
nameserver-policy:
  "geosite:cn,private":
    - https://223.5.5.5/dns-query
    - https://doh.pub/dns-query
  "geosite:gfw":
    - https://8.8.8.8/dns-query#RULES&ecs=223.5.5.0/24
    - https://1.1.1.1/dns-query
nameserver:
  - https://223.5.5.5/dns-query
  - https://doh.pub/dns-query
  - https://1.1.1.1/dns-query  # 含境外兜底
方案一：所有域名一律走国内 DoH，境外域名通过 sniffer 嗅探真实域名后再由 rules 决定是否走代理——DNS 层不区分，由流量层处理。
方案二：DNS 层就做分流，gfw 列表域名在解析阶段就走代理 DoH，ECS 参数 ecs=223.5.5.0/24 让 Google DNS 返回大陆友好 IP，减少解析绕路。
③ default-nameserver 注释
方案一注释明确写出 default-nameserver 的用途：仅用于解析 doh.pub 这个域名（即 DoH 服务器域名的 bootstrap 解析），不参与常规流量 DNS。方案二注释省略，功能相同。两者 default-nameserver 值一致（223.5.5.5 / 119.29.29.29）。
选型建议

选方案一（纯国内）

配置简单，零境外 DNS 流量，依赖 sniffer 做流量层分流。适合节点覆盖全、sniffer 规则完善的场景，或追求最少配置项的用户

选方案二（分流）

DNS 层预判分流，gfw 域名解析更准确，ECS 可优化 Google/YouTube 等 CDN IP。适合对 GFW 域名延迟敏感、节点质量稳定的场景

两者共同依赖

fake-ip-filter 必须含 geosite:cn；NTP / STUN / Tailscale 条目缺一不可；sniffer 的 skip-dst-address 私有网段不能省

Nikki 路由器特有

auto-route/auto-redirect: false，路由完全由 nftables 管；store-fake-ip: true 保证重启不丢映射；dns-hijack 劫持 any:53

✅
两套配置均在 ImmortalWrt 25.12.0 + Nikki 插件下验证可用。替换 Nikki 配置编辑器中的内容并重启 Nikki 即可生效。
路由器透明代理架构要点 下次配置直接套用
⚠️
以下四条结论专属于 路由器 + Nikki TUN + nftables 透明代理 拓扑，本机代理（macOS/Windows）行为不同，不可混用。
网络拓扑
LAN 设备 → nftables 劫持全部流量 → Mihomo TUN (nikki)
↓ rules 判断
代理节点 或 DIRECT
关键：nftables 兜底劫持所有出站流量，包括 Mihomo 自己发出的 DNS 查询，所以 Mihomo DNS 的"直连"实际上会再被 nftables 截回，走一遍 rules。
规则 1 respect-rules 路由器必须 false
respect-rules: true 意味着 Mihomo 自己发出的 DNS 查询也要先过 rules 才决定走哪个出口。路由器场景下这造成循环依赖：rules 匹配域名需要 DNS，但 DNS 查询又在等 rules——死锁。
false 时 DNS 直接出网卡，不过 rules，由 nftables 兜底处理，不会死锁。
true 适用场景：macOS/Windows 本机代理，Mihomo 能区分自身 DNS 流量，不存在循环。
设置 DNS 查询走规则 路由器透明代理 本机代理
false ❌ 直连（nftables 兜底） ✅ 必须用 可用
true ✅ 过 rules ❌ 死锁 ✅ 更精确
规则 2 8.8.8.8 DoH 天然走代理，不怕被封
respect-rules: false 下，Mihomo DNS 模块发出的 DoH 请求"直连"出网卡，但 nftables 会把它劫持回 Mihomo，再走一遍 rules。
8.8.8.8 命中 GEOIP,US → 走代理出去。实际路径：
Mihomo DNS → 直连出网卡 → nftables 劫持 → 回 Mihomo rules → 代理节点 → 8.8.8.8
因此 https://8.8.8.8/dns-query 实际从代理隧道发出，国内运营商看不到，不存在被封问题。#RULES 只是 Mihomo 本地标签，不出现在网络请求里。
规则 3 nameserver-policy 分流：cn/private 国内，gfw 代理 DoH
分流 key 用 "geosite:gfw"，不加 tld-!cn。
加了 tld-!cn 会把所有境外 TLD（.io/.dev/.app 等）都打进代理 DoH，覆盖范围过大，可能导致部分合规境外域名解析绕路。
geosite:gfw 列表本身已覆盖主流被墙域名，配合 sniffer 兜底，足够用。
规则 4 proxy-server-nameserver 用 DoH，防节点域名污染
proxy-server-nameserver 专门用来解析代理节点的域名（如 hk4.example.com）。
必须用 DoH 或可信 DNS（223.5.5.5 + https://sh.dns44.cn:44443/dns-query），否则节点域名被运营商 DNS 污染，代理连接全部失败。
这是代理能不能建立连接的前提，优先级高于其他 DNS 配置。
