Nikki / Mihomo 透明代理
DNS 分流：两种策略对比

基于 fake-ip 增强模式，国内域名走真实 IP + 国内 DoH，两种方案的区别集中在 GFW 域名策略与兜底 nameserver 配置。

ℹ️
运行环境 · ImmortalWrt 25.12.0 · NanoPi R5C · Nikki（Mihomo 内核）· TUN stack=mixed · nftables 透明代理 · fake-ip 198.18.0.1/16
方案对比总览 核心差异
方案一 · 保守兜底
GFW 域名走代理 DoH；nameserver 保留国外兜底（1.1.1.1），未命中策略的域名由国内 + 国外 DoH 共同解析
GFW nameserver-policy key "geosite:gfw"
nameserver（兜底） 223.5.5.5 / doh.pub / 1.1.1.1
适合场景 希望境外未知域名也能正常解析；可接受少量境外 DNS 请求
方案二 · 纯国内兜底
GFW + 非中国顶级域均走代理 DoH；nameserver 仅国内 DoH，未命中策略的域名全走国内解析
GFW nameserver-policy key "geosite:gfw,tld-!cn"
nameserver（兜底） 223.5.5.5 / doh.pub（纯国内）
适合场景 全力走代理解析境外域名；对隐私要求高，不希望直连境外 DNS
方案一 · 解析流程
DNS 查询 → geosite:cn / private → 223.5.5.5 / doh.pub 真实 IP，直连 CDN 最优
DNS 查询 → geosite:gfw → 8.8.8.8#RULES + ECS / 1.1.1.1 经代理解析，ECS 返回大陆友好 IP
DNS 查询 → 其余域名 → 223.5.5.5 / doh.pub / 1.1.1.1（兜底）
方案二 · 解析流程
DNS 查询 → geosite:cn / private → 223.5.5.5 / doh.pub 真实 IP，直连 CDN 最优
DNS 查询 → geosite:gfw + tld-!cn → 8.8.8.8#RULES + ECS / 1.1.1.1 覆盖更广，所有境外顶级域均走代理
DNS 查询 → 其余域名 → 223.5.5.5 / doh.pub（纯国内兜底）

关键差异详解 3 处变化
⚠️
两方案共用所有其他配置（TUN、sniffer、fake-ip-filter、profile 等），仅以下 3 处不同。
① nameserver-policy 中 GFW 的 key
方案一 V1
"geosite:gfw":
  - https://8.8.8.8/dns-query#RULES&ecs=...
  - https://1.1.1.1/dns-query
方案二 V2
"geosite:gfw,tld-!cn":
  - https://8.8.8.8/dns-query#RULES&ecs=...
  - https://1.1.1.1/dns-query
tld-!cn 意为"顶级域不是 .cn 的所有域名"。方案二将其与 gfw 合并，覆盖范围更广：即使某域名不在 GFW 列表但 TLD 为境外（如 .io/.dev/.app），也会走代理 DoH 解析，避免 geosite:gfw 遗漏导致的污染。
② nameserver 兜底列表
方案一 V1
nameserver:
  - https://223.5.5.5/dns-query
  - https://doh.pub/dns-query
  - https://1.1.1.1/dns-query
方案二 V2
nameserver:
  - https://223.5.5.5/dns-query
  - https://doh.pub/dns-query
  # 无 1.1.1.1
方案一在兜底 nameserver 中保留了 1.1.1.1，这意味着未被 policy 命中的陌生境外域名可以直连 Cloudflare 解析——在代理节点较少时更稳健，但会有少量境外 DNS 流量直连。方案二去除境外兜底，所有未命中域名都走国内 DoH，隐私更好但对 geosite 数据库的完整性依赖更高。
③ 实际效果对比
方案一
• 境外冷门域名（不在 gfw 列表）可能直连国外 DNS 解析
• 兜底更稳，节点异常时降级平滑
• 适合节点覆盖不全、追求可用性的场景
方案二
• 所有境外 TLD 均走代理 DoH，DNS 不泄漏
• 需要代理节点稳定在线，否则境外域名解析失败
• 适合节点质量高、隐私优先的场景
场景推荐

选方案一（保守兜底）

节点数量有限 / 经常出现节点全挂情况 / 家庭网络多设备使用、容错优先 / 访问冷门境外网站较多

选方案二（纯国内兜底）

节点稳定可靠 / 对 DNS 隐私有要求 / 不想任何境外 DNS 流量直连出去 / 机场订阅覆盖主流境外服务

两者共同要求

fake-ip-filter 中必须含 geosite:cn，否则国内域名也返回假 IP 导致 CDN 调度失效；NTP / STUN / Tailscale 条目缺一不可

Nikki 路由器特有注意

auto-route: false · auto-redirect: false，路由完全由 Nikki 的 nftables 规则管理；store-fake-ip: true 保证重启后 fake-ip 映射不丢失

✅
两套配置在 ImmortalWrt 25.12.0 + Nikki 插件环境下均经过验证，直接粘贴替换 /etc/mihomo/config.yaml（或 Nikki UI 配置编辑器）并重启 Nikki 即可生效。
