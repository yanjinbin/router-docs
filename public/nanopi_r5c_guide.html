NanoPi R5C · 刷入 ImmortalWrt 完整教程

Mac 系统·TF 卡引导·R5C 作主路由·AX82U 作 AP

📖 官方说明书：FriendlyELEC NanoPi R5C 官方 Wiki（中文）

为什么选 R5C

性价比合适
RK3568B2 内置 AES-NI 硬件加速单元，Mihomo 代理下 TLS 解密不走软件路径，千兆线速无压力。相比 R5S（同款 SoC 但封装更厚、价格更高），R5C 更紧凑，咸鱼二手价格更友好。
准备材料
所需物品说明
多功能拓展坞 必须 需要同时具备 TF 卡插槽（把 TF 卡当 U 盘读写）和 RJ45 网口。推荐宏碁多功能拓展坞，约 ¥60，含 TF 卡槽 + RJ45 + Type-C，一个搞定所有接口需求。MacBook 本身无 SD 卡槽和有线网口，缺一不可。
网线 必须 刷机全程必须走有线，一根普通超五类网线即可。Wi-Fi 刷机存在中断风险，不建议使用。
电源适配器 ⚠ 注意电压 电压必须为 5V，不可超过 5V，否则会烧毁主板。电流最低 2A，2A / 3A / 4A 均可；若外接移动硬盘等高功耗设备，建议选 3A 或 4A。接口为 USB-C。

⚠ 注意：部分多档位充电头会输出多种电压（如 5V 3A 兼 9V 1.5A），这类充电头不可使用，9V 档位会直接烧板。请选用最高输出电压不超过 5V 的专用适配器。
TF 卡8 GB 以上，Class 10。用拓展坞的 TF 卡槽直接读写，无需单独读卡器。
引导固件FriendlyELEC 官方网盘 → R5C → sd-friendlywrt 镜像。
目标固件firmware-selector.immortalwrt.org 搜 NanoPi R5C，下载 .img.gz。
balenaEtcher（Mac）etcher.balena.io 下载 .dmg 安装。
⚠ 不要选 iStoreOS：友善 R5C 上 iStoreOS 容易崩溃断网，稳定性差。目标固件请选 ImmortalWrt，不要被插件商店的便利性所诱导，稳定运行才是软路由第一要务。
关于 openwrt.ai：openwrt.ai 也支持在线定制 OpenWrt 固件镜像，操作较方便。但其软件包镜像源均为境外源，国内下载速度慢、稳定性差，不如 ImmortalWrt 适合国内使用场景。本教程仍推荐 ImmortalWrt。
Safari 会自动解压 .gz 变成 .img，直接用即可。balenaEtcher 支持直接烧 .img.gz，不要手动解压。
阶段一 制作 TF 引导卡 约 5 分钟
1
TF 卡插入读卡器，连接 Mac
2
打开 balenaEtcher 烧录官方固件
Flash from file → 选 sd-friendlywrt 固件 → Select target 选 TF 卡（注意别选外置硬盘）→ Flash!
Mac 会弹出 Touch ID 或密码授权，正常现象，允许即可。
3
把 ImmortalWrt 固件拷进 TF 卡
烧录完成后 Mac 弹出"无法读取磁盘"提示 → 点忽略（绝对不要点初始化）。在 Finder 左栏找到 BOOT 分区，将 ImmortalWrt 固件拖入根目录，改名为 immortalwrt.img.gz。
找不到 BOOT 分区也没关系，后续可在后台网页直接上传固件。
4
在 Finder 右键安全弹出读卡器，拔出 TF 卡
阶段二 连接与启动 MacBook 网线直连 R5C
1
R5C 完全断电，插入 TF 卡
2
网线一端插 R5C 的 LAN 口，另一端通过 USB-C 转 RJ45 插 MacBook
3
关闭 Mac 的 Wi-Fi
菜单栏 Wi-Fi 图标 → 关闭 Wi-Fi。不关 Wi-Fi 会导致浏览器走 Wi-Fi 网关，永远访问不到 R5C 后台。
4
给 R5C 接通电源
RK3568 芯片硬件启动优先级写死为 TF 卡 → eMMC，插卡即自动从 TF 启动，无需按任何键。
若无法从 TF 启动（eMMC 有不兼容固件）：断电 → 按住 Mask 键不松手 → 通电 → 保持 3~5 秒后松开，强制引导。
5
确认 Mac 有线已获取到 IP
系统设置 → 网络 → 以太网，显示"已连接"且有 IP 地址（如 192.168.2.x）即可。
阶段三 确认后台地址并登录
1
打开 Mac 终端，运行以下命令查找网关 IP
netstat -rn | grep default | awk '{print $2}'

输出的 IP 就是 R5C 后台地址，直接在浏览器打开。规律：Mac 拿到的 IP 是 192.168.X.Y，后台就是 192.168.X.1。

192.168.2.1TF 卡临时系统（官方 FriendlyWrt）默认地址
192.168.1.1eMMC ImmortalWrt 刷入后默认地址
2
浏览器访问后台，登录
用户名 root，密码通常为空或 password。
阶段四 将 ImmortalWrt 写入 eMMC
方法一（推荐）：网页后台一键刷入
1
进入 系统 → eMMC 刷机助手
2
上传 ImmortalWrt 固件
点击"浏览"选择之前存入 BOOT 分区的固件，或从 Mac 下载目录选取，点击"开始刷机"。
3
等待进度条 100%，提示写入成功
写入过程中不要断电、不要关闭浏览器，否则 eMMC 可能写入不完整变砖。
方法二（备选）：SSH 命令行写入
1
SSH 连接软路由
ssh root@192.168.2.1
2
确认 eMMC 盘符
lsblk

找容量 32 GB 那个设备，通常是 mmcblk0。

3
执行写入脚本
emmc-install

按提示选择固件路径（之前拷到 BOOT 分区的文件），确认执行。

阶段五 拔卡重启，启动新系统
1
R5C 断电
2
拔掉 TF 卡
不拔卡则下次依然进入 TF 临时系统。
3
重新通电，等待约 30 秒
浏览器访问 192.168.1.1 进入 ImmortalWrt 后台，用户名 root，密码 password。
阶段六 组网：R5C 主路由 + AX82U 作 AP 无线访问后台
光猫 WAN → R5C WAN口 → R5C LAN口 → AX82U LAN口（AP模式）→ Wi-Fi → 设备

AX82U 改 AP 模式：

1
进入 AX82U 后台 192.168.50.1
2
高级设置 → 无线路由器（Operation Mode）→ 切换为 Access Point 模式
切换后 AX82U 的 DHCP 自动关闭，只负责发射 Wi-Fi，IP 分配全交给 R5C。
3
网线接法：R5C 任意 LAN 口 → AX82U 的 LAN 口
AP 模式下接 LAN 口，不是 WAN 口。

无线访问 R5C 后台：

MacBook 连上 AX82U 的 Wi-Fi 后，浏览器直接访问 192.168.1.1 即可管理 R5C，无需插网线。此时不需要关 Wi-Fi，目标 IP 在局域网内，不存在路由冲突。

如需确认后台 IP，连上 Wi-Fi 后在终端运行：

netstat -rn | grep default | awk '{print $2}'
阶段七 华硕 AiMesh 组网（AP 模式下） R5C 主路由 + RAX80 控制节点 + AX82U 卫星节点，全屋无缝漫游
光猫 WAN → R5C WAN口 → R5C LAN口 ──网线──→ RAX80 LAN口（AiMesh Router / AP）
                                                        ↕ 无线 Backhaul（或网线）
                                                  AX82U（AiMesh Node）→ Wi-Fi → 设备
AiMesh 核心原理：华硕 AiMesh 让多台华硕路由器组成一个 SSID 的统一无线网络，设备移动时自动切换到信号最强的节点（802.11r/k/v 无缝漫游）。R5C 只负责路由/DHCP，AiMesh 网络完全由华硕路由器自管。

第一步：准备工作

1
RAX80 和 AX82U 全部恢复出厂设置
长按 Reset 键 5–10 秒，等待重启完成。确保两台设备都是"全新"状态再配对，避免旧配置干扰。
2
固件版本一致（推荐梅林 Merlin）
AiMesh 配对对固件版本敏感。两台都刷官方固件或同版本梅林，混搭不同版本可能配对失败。

第二步：配置 RAX80 为 AiMesh Router（AP 模式）

3
RAX80 通过网线连接 R5C 的 LAN 口（接 LAN，不接 WAN）
此时 RAX80 会从 R5C 的 DHCP 获取一个 IP，例如 192.168.1.x。
4
进入 RAX80 后台，找到它的 IP
在 R5C OpenWrt 后台 → 网络 → DHCP/DNS → 活跃租约，找到 RAX80 分配到的 IP。也可用手机连 RAX80 发出的初始 Wi-Fi，访问 192.168.50.1。
5
高级设置 → 无线路由器 → Operation Mode → 切换为 Access Point 模式
切换后 RAX80 的 WAN 口和 DHCP 均停用，由 R5C 统一分配 IP。RAX80 重启后仍从 R5C DHCP 获取 IP。
6
设置 RAX80 的无线 SSID 和密码
记住这组 SSID/密码，AX82U 加入 AiMesh 后会自动同步为相同的 SSID。

第三步：将 AX82U 加入 AiMesh 作为 Node

7
AX82U 上电，放在离 RAX80 约 1–2 米处（配对阶段需要强信号）
AX82U 出厂 / 恢复出厂后会自动发出名为 ASUS_AX82U_Setup 的临时 Wi-Fi，等待被配对。
8
进入 RAX80 后台 → AiMesh → 搜索新节点 → 选择 AX82U → 确认添加
RAX80 会自动推送 SSID/密码/配置到 AX82U，过程约 3–5 分钟，期间 AX82U 会重启。完成后两台共享同一 SSID。
9
配对完成后将 AX82U 移至目标位置
放在与 RAX80 之间有一定重叠覆盖的位置（信号约 -65 dBm 以上）。Backhaul 默认走 5 GHz 无线；若拉一根网线给 AX82U 的 LAN 口，切换为有线 Backhaul，延迟和稳定性大幅提升。

第四步：验证与调优

10
RAX80 后台 → AiMesh → 查看节点状态
AX82U 应显示为"已连接"绿色节点，以及 Backhaul 类型（无线/有线）和链路速率。
11
开启 Smart Connect（可选）：自动将设备引导至最优频段
无线 → Smart Connect → 开启。2.4G / 5G 统一 SSID，路由器自动选频，适合混合设备家庭。
12
开启 Roaming Assist（漫游辅助）
无线 → 专业设置 → Roaming Assist → 开启，设定 RSSI 阈值（建议 -70 dBm）。手机移动时，当前节点信号低于阈值会主动踢出设备，让其重新关联更近的节点。
⚠️ 常见问题
找不到 AX82U 节点？确认 AX82U 已恢复出厂，且与 RAX80 在同一楼层，搜索时距离不超过 3 米。
配对后 SSID 消失？等待约 5 分钟，AX82U 完成固件同步重启后 SSID 恢复正常。
漫游切换慢？优先启用有线 Backhaul（网线接 AX82U 的 LAN 口），并开启 802.11r（快速 BSS 切换）。梅林固件路径：无线 → 专业设置 → Enable 802.11r。
RAX80 后台入口？AP 模式后默认访问 http://router.asus.com 或从 R5C DHCP 租约查到 RAX80 的 IP 直接访问。

TF 卡保留与重复使用

随时可再次从 TF 引导：断电 → 插入 TF 卡 → 通电，R5C 自动优先从 TF 启动。
回到 eMMC 系统：断电 → 拔掉 TF 卡 → 通电，即可切回。
强烈建议永久保留这张卡作为救砖盘，贴标签注明"R5C 救砖盘"存好。eMMC 系统崩溃时插卡即可修复，节省大量时间。
eMMC 固件大版本升级后，建议同步更新 TF 卡镜像，避免内核版本不兼容。
系统性能优化 sysctl · Nikki UCI
以下两组优化适用于 ImmortalWrt 25.12.0 + Nikki，在 NanoPi R5C（192.168.1.1，SSH 别名 R5C）上经过验证。每次大版本升级固件后需重新确认 sysctl 参数是否保留。
1 内核参数优化（/etc/sysctl.conf）
写入后执行 sysctl -p 立即生效，无需重启。
参数 值 说明
net.core.rmem_max 16777216 Socket 接收缓冲区上限 16 MB，改善大带宽/高延迟场景吞吐
net.core.wmem_max 16777216 Socket 发送缓冲区上限 16 MB
net.ipv4.tcp_rmem 4096 87380 16777216 TCP 接收缓冲区：min / default / max，max = 16 MB
net.ipv4.tcp_wmem 4096 65536 16777216 TCP 发送缓冲区：min / default / max，max = 16 MB
net.ipv4.tcp_mtu_probing 1 开启 MTU 探测，避免 ICMP 黑洞导致连接卡死
net.netfilter.nf_conntrack_max 131072 conntrack 表最大连接数 128 K，防止 NAT 表满后丢包
net.ipv4.tcp_fastopen 3 同时开启客户端 + 服务端 TFO，减少握手 RTT
写入 /etc/sysctl.conf 并立即生效 cat >> /etc/sysctl.conf << 'EOF' net.core.rmem_max=16777216 net.core.wmem_max=16777216 net.ipv4.tcp_rmem=4096 87380 16777216 net.ipv4.tcp_wmem=4096 65536 16777216 net.ipv4.tcp_mtu_probing=1 net.netfilter.nf_conntrack_max=131072 net.ipv4.tcp_fastopen=3 EOF sysctl -p 
cat >> /etc/sysctl.conf << 'EOF'
net.core.rmem_max=16777216
net.core.wmem_max=16777216
net.ipv4.tcp_rmem=4096 87380 16777216
net.ipv4.tcp_wmem=4096 65536 16777216
net.ipv4.tcp_mtu_probing=1
net.netfilter.nf_conntrack_max=131072
net.ipv4.tcp_fastopen=3
EOF
sysctl -p
验证参数是否生效 sysctl net.core.rmem_max net.core.wmem_max net.ipv4.tcp_mtu_probing net.netfilter.nf_conntrack_max net.ipv4.tcp_fastopen && sysctl net.ipv4.tcp_rmem net.ipv4.tcp_wmem 
sysctl net.core.rmem_max net.core.wmem_max \
      net.ipv4.tcp_mtu_probing net.netfilter.nf_conntrack_max \
      net.ipv4.tcp_fastopen
sysctl net.ipv4.tcp_rmem net.ipv4.tcp_wmem
2 Nikki UCI 配置优化
通过 UCI 调整三处参数：日志级别降噪、清理 Cron 频率（30 分钟一次）、清理阈值（5 MB），commit 后重启 Nikki 生效。
UCI 键 值 说明
nikki.config.log_level error 仅记录 error 级别，减少 eMMC 写入，降低 logread 噪音
nikki.config.cron_clean */30 * * * * 每 30 分钟清理一次临时文件，默认值通常更频繁或更稀少
nikki.config.clean_threshold 5 临时目录超过 5 MB 才触发清理（单位 MB）
UCI 写入 + commit + 重启 Nikki uci set nikki.config.log_level='error' uci set nikki.config.cron_clean='*/30 * * * *' uci set nikki.config.clean_threshold='5' uci commit nikki service nikki restart 
uci set nikki.config.log_level='error'
uci set nikki.config.cron_clean='*/30 * * * *'
uci set nikki.config.clean_threshold='5'
uci commit nikki
service nikki restart
验证 UCI 参数 uci show nikki.config.log_level nikki.config.cron_clean nikki.config.clean_threshold 
uci show nikki.config.log_level \
         nikki.config.cron_clean \
         nikki.config.clean_threshold

# nikki.config.clean_threshold='5'
