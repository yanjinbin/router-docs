五层架构 & 决策流程

从下游设备发出请求，到 ISP 骨干网落地目标服务器，途经物理网卡 → Linux 内核 netfilter → fw4/Nikki nftables → Mihomo 应用层 → ppp0 出口的完整五层路径。

ℹ️
运行环境：ImmortalWrt 25.12.0 · NanoPi R5C · Nikki（Mihomo 内核）· TUN stack=mixed · nftables 透明代理 · fake-ip 198.18.0.1/16 · PPPoE WAN（华数 / CQBN · MTU 1492）。
五层架构图 总览

按层切割整个流量链路，每一层独立负责一组职责。纵向箭头表示数据流方向，左侧竖排标签标注所属层次。

图1 · Mihomo 完整流量路径架构图 — 物理层 / 内核层 / 防火墙层 / 应用层 / 出口层

物理层

eth0（LAN 入口）· tun0（Mihomo 虚拟网卡）· ppp0（PPPoE WAN 出口）三块网卡并列，流量入口与出口明确分离

内核层

Linux netfilter 四个 hook：PREROUTING（TPROXY + DNS 劫持）· FORWARD · OUTPUT（跳过自身）· POSTROUTING（MASQUERADE）

防火墙层

fw4 读取 UCI /etc/config/firewall 生成 table fw4；Nikki 在 /etc/nftables.d/ 追加独立 chain，互不干扰

应用层

Mihomo 进程（用户态）三大模块：DNS :1053（fake-ip）· 规则匹配 :7893 · 代理组选节点（fallback / url-test）

出口层

三条并列路径汇聚到 ppp0：强制绕行 DIRECT · GEOIP CN 直连 · 代理出境（VLESS/Hy2 + 住宅 IP 中转）

eth0 → tun0 · 入站路径

1. 下游设备发包，网关指向路由器 192.168.1.1
2. eth0 接收，进入内核 PREROUTING
3. DNS 查询被劫持到 :53 → :1053（Mihomo）
4. 普通流量被 TPROXY mark 0x1 → ip rule → tun0
5. tun0 将流量送入 Mihomo 规则引擎

Mihomo → ppp0 · 出站路径

规则匹配后决定 DIRECT 或代理
DIRECT 流量经内核 POSTROUTING MASQUERADE → ppp0
代理流量封装成 VLESS/Hy2，经代理节点落地
住宅 IP 中转 dialer-proxy 用于 AI 服务防封
响应包原路返回，解包后交回下游设备
完整决策流程图 v2 决策链

将架构图中每一层的判断逻辑串联成决策链，追踪一个 DNS 查询和一次真实连接请求的完整生命周期。
虚线箭头（---►）表示"重新入栈"：设备拿到 fake-ip 后重新发起 TCP/UDP 连接，流量再次经过 PREROUTING 被 TPROXY 劫持送入规则引擎。

图2 · Mihomo 完整流量路径决策图 v2 — DNS 分流 + fake-ip + 规则匹配 + 三路出口
1
PREROUTING · 三步拦截
Nikki chain 在 PREROUTING 注入三条规则，按优先级顺序执行：
① IPv6 防泄漏：::/0 REJECT，最高优先，防止 IPv6 流量绕过代理直接出境；
② DNS 劫持：UDP/TCP :53 → 127.0.0.1:1053，强制所有 DNS 查询走 Mihomo；
③ TPROXY：TCP/UDP 普通流量打 mark 0x1，ip rule table 100 将其路由到 tun0 虚拟网卡。
2
fw4 与 Nikki · 独立共存
fw4 读取 /etc/config/firewall（UCI）生成 table fw4，管理 zone/forward/NAT 策略。
Nikki 将规则写入 /etc/nftables.d/ 目录，fw4 重启时通过 include 机制加载，不会被覆盖。
两者在不同 chain 运行，TPROXY mark、DNS 劫持、IPv6 block 均由 Nikki chain 负责，fw4 不感知代理逻辑。
3
fake-ip · DNS 分流逻辑
Mihomo DNS 模块监听 :1053，以 fake-ip 模式响应所有查询：
· CN 域名（geosite:cn）→ 国内 DoH（阿里 223.5.5.5 / 腾讯 doh.pub）解析，返回真实 IP 或 fake-ip；
· GFW 域名（geosite:gfw）→ 8.8.8.8#RULES 走代理 DoH + ECS，返回 198.18.x.x fake-ip；
· 设备拿到 fake-ip 后发起真实连接，流量再次入栈被 TPROXY 劫持送入规则引擎。
4
规则匹配 · 三级优先链
Mihomo 规则链按优先级依次命中：
① bypass 强制绕行：B站、抖音、淘宝、微博、小米、爱奇艺等国内大厂域名 → DIRECT，跳过代理组；
② DOMAIN-SUFFIX / GEOIP CN：目标 IP 属国内 → DIRECT，无需代理节点；
③ MATCH：兜底规则，命中代理组 → 选节点出境。
bypass 先于 GEOIP CN，确保明确标注的国内应用不会被误代理。
5
代理出境 · 住宅 IP 中转
代理节点支持 VLESS · Hy2（Hysteria2）· AnyTLS 协议，fallback / url-test 自动选优。
对 AI 服务（ChatGPT、Claude 等）启用 dialer-proxy：流量先到 VPS 节点，再通过 SOCKS5 住宅 IP（San Jose / Tokyo）落地，
防止数据中心 IP 被风控封号。
6
POSTROUTING · 统一 NAT 出境
三路出口（bypass DIRECT · GEOIP CN · 代理）最终汇聚后，经内核 POSTROUTING 的 NAT MASQUERADE，
将源地址伪装为路由器 ppp0 IP（华数/CQBN 拨号地址），再由 ppp0（PPPoE · MTU 1492）发往 ISP 骨干网。
关键机制要点 深度
TPROXY vs 传统 redirect：透明代理不改写目标 IP
传统 iptables REDIRECT 把目标 IP 改写为 127.0.0.1，Mihomo 无法获知原始目标。
TPROXY 保留原始目标 IP/Port，Mihomo 通过 SO_ORIGINAL_DST 或 TUN 接口直接读取目标地址，用于 DOMAIN-SUFFIX、GEOIP 等规则精确匹配。
mark 0x1 → ip rule table 100 → tun0 是 TPROXY 策略路由的标准三段式。
fake-ip 与 sniffer 的协作
fake-ip 让 Mihomo 在 DNS 解析阶段即可建立域名→连接的映射，无需等待实际 IP。
sniffer（TLS SNI / HTTP Host 探测）在连接建立后从握手包中还原真实域名，
用于修正"纯国内 DNS 方案"中无 nameserver-policy 时 DOMAIN 规则无法命中的问题。
OUTPUT hook · Mihomo 自身流量跳过 TPROXY
Mihomo 进程本身发出的流量（出向代理节点的连接）不能再被 TPROXY 拦截，否则死循环。
Nikki 在 OUTPUT hook 通过 meta skuid != mihomo 或 cgroup/uid 匹配，跳过 Mihomo 进程的出站流量。
这也是为什么代理节点的域名解析需要 proxy-server-nameserver 单独配置可信 DoH。
IPv6 防泄漏 · 最高优先级的必要性
大多数代理协议不支持 IPv6 隧道，若不拦截则 IPv6 流量直接经 WAN 口出境，绕过代理暴露真实位置。
Nikki chain 将 ::/0 REJECT 置于最高优先级（优先于 DNS 劫持和 TPROXY），
确保任何 IPv6 数据包在 PREROUTING 最早时机被丢弃，不进入后续规则处理。
PPPoE · MTU 1492 与 MSS Clamp
PPPoE 在以太网 MTU 1500 之上增加 8 字节 header，可用 MTU 降为 1492。
若不配置 MSS Clamp（tcp-mss 1452），TCP 握手协商的 MSS 可能超出 PPPoE 帧大小，导致大包传输失败（网页打开慢、下载卡顿）。
OpenWrt/ImmortalWrt 通过 nftables 的 tcp flags syn tcp option maxseg size set rt mtu 自动处理。
三条出口路径对比 路径
强制绕行 DIRECT
触发条件：bypass 规则命中（B站、抖音、淘宝、微博、小米、vivo、爱奇艺等）
路径：Mihomo → 内核 POSTROUTING → ppp0 → ISP
延迟：最低，无代理开销
用途：国内大厂应用防止代理导致的账号风控或 CDN 绕路变慢
GEOIP CN 直连
触发条件：目标 IP 属 GEOIP CN 数据库
路径：Mihomo → 内核 POSTROUTING → ppp0 → ISP
延迟：低，国内骨干网直连
用途：覆盖 bypass 未列出的国内 IP 段，保证国内访问速度
代理出境
触发条件：MATCH 兜底 / GFW 域名命中
路径：Mihomo → VPS 节点（VLESS/Hy2）→ [住宅 IP SOCKS5] → 目标
延迟：+30~120ms（节点质量决定）
用途：GFW 封锁域名、AI 服务、境外流媒体
