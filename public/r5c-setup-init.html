2 配置 WAN PPPoE 拨号 👤 人工介入
刷完默认 WAN 是 DHCP，光猫桥接 / 拨号上网需改成 PPPoE。两种方式任选其一：LuCI 网页改，或 SSH 进去用 UCI 改（更快，可直接贴给 Claude 但建议刷完先手动联网）。
方式 A · LuCI 网页 
网络 → 接口 → WAN → 编辑
  协议 (Protocol)        改为  PPPoE
  PAP/CHAP 用户名         填    宽带账号
  PAP/CHAP 密码          填    宽带密码
保存并应用 → 等待拨号，WAN 拿到公网 IP 即成功
方式 B · SSH + UCI（更快） shell 
# 在路由器 shell 执行，把账号密码替换成自己的宽带凭据
uci set network.wan.proto='pppoe'
uci set network.wan.username='你的宽带账号'
uci set network.wan.password='你的宽带密码'
uci commit network
/etc/init.d/network restart

# 验证：看 WAN 是否拿到公网 IP（非 192.168/100.64 段）
ifstatus wan | grep -E '"address"|"up"'
ℹ️
电信 / 联通常见账号格式 手机号@pppoe 或纯宽带号；移动多为纯账号。拨号失败先核对账号格式、确认光猫已是桥接（Bridge）模式。
3 生成 SSH 密钥并建立 R5C 别名 👤 人工介入 · 在你的电脑
给 R5C 单独生成一对 RSA 密钥（不复用日常 key），公钥灌进路由器实现免密登录，再在 ~/.ssh/config 配 R5C 别名——之后 Claude 直接 ssh R5C 接管。
Step 1 · 生成密钥对 本机 shell 
# 在 ~/.ssh 下生成 id_r5c / id_r5c.pub（一路回车，可不设密码短语）
ssh-keygen -t rsa -C "your-username@gmail.com" -f ~/.ssh/id_r5c
Step 2 · 公钥灌入路由器 本机 shell 
# 默认地址 192.168.1.1，按提示输入 root 密码一次
ssh-copy-id -i ~/.ssh/id_r5c.pub root@192.168.1.1

# 若没有 ssh-copy-id，手动追加：
cat ~/.ssh/id_r5c.pub | ssh root@192.168.1.1 "cat >> /etc/dropbear/authorized_keys"
Step 3 · 配置 ~/.ssh/config 别名 本机 
# 追加到 ~/.ssh/config —— 之后 `ssh R5C` 即免密登录
Host R5C
    HostName 192.168.1.1
    User root
    IdentityFile ~/.ssh/id_r5c
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
✅
验证：执行 ssh R5C 应免密直接进入路由器。StrictHostKeyChecking no + UserKnownHostsFile /dev/null 让刷机后 host key 变更时不报错、不阻塞 Claude 自动重连。
4 手动安装 Nikki + 贴 mihomo 配置 👤 人工介入
⚠️
Nikki 是第三方 feed 包，官方源里没有，必须先手动装好；不装的话第 ⑤ 段套装里 sysctl 后半的 nikki 调优会被脚本守卫自动跳过。装完 Nikki 再贴 mihomo yaml 配置，才算具备 Claude 接管的前提。
Step 1 · 安装 Nikki：登录 R5C shell（SSH 或 LuCI 的 ttyd 终端），先加 Nikki feed（一次性，用 gh-proxy 加速），再用 apk 安装内核 + LuCI 应用 + 中文翻译。装完在 LuCI 左侧应能看到 「Nikki」 菜单。
R5C shell / ttyd 执行 shell 
# 加 Nikki feed —— 只需运行一次（gh-proxy 加速 GitHub）
wget -O - https://gh-proxy.com/https://github.com/nikkinikki-org/OpenWrt-nikki/raw/refs/heads/main/feed.sh | ash

# for apk
apk update
apk add nikki
apk add luci-app-nikki
apk add luci-i18n-nikki-zh-cn

5 Claude Code 接管 · 复现套装逐段实施 🐙 Claude 实施 · 5 段提示词
🐙
在能 ssh R5C 的电脑上启动 Claude Code，逐段复制下面提示词发给它（不要一次全发）。每段都内置了「先确认再执行」「逐项验证」逻辑，按 ①→②→③→④→⑤ 顺序即可。
1装回官方软件包（主题 + 中文翻译）
帮 R5C 装回官方软件包：先 apk update（必须成功，否则索引旧了会静默漏装），再 apk add luci-theme-openwrt luci-i18n-base-zh-cn luci-i18n-dashboard-zh-cn luci-i18n-eqos-zh-cn luci-i18n-homeproxy-zh-cn luci-i18n-package-manager-zh-cn luci-i18n-statistics-zh-cn luci-i18n-ttyd-zh-cn 不要装 cpufreq。装完逐个验证已安装。
⚠️
apk update 必须先成功，否则索引旧 → 静默漏装（实测漏过包）
❌
不装 cpufreq（用户明确不要）
🔗
装 i18n 翻译会自动带对应 luci-app-* 依赖
2eMMC extroot 扩容（overlay 迁到 56G）🐙+👤 需人工核对重启
帮 R5C 做 eMMC extroot 扩容，把系统 overlay 从小 loop 设备迁到 56G 的 /dev/mmcblk1p3。 步骤： 1. 先 df -h / mount / uci show fstab / block info 确认现状，报告 /overlay/upper 大小； 2. 清空 /mnt/mmcblk1p3 旧 upper/work（保留 lost+found）并重建空目录； 3. cp -a /overlay/upper/. /mnt/mmcblk1p3/upper/ 复制当前运行系统可写层，复制后对比两边大小一致； 4. 改 fstab：target='/overlay' 那条 mount 的 uuid 指向 mmcblk1p3 的 UUID（现查不写死）且 enabled='1'，单独挂 /mnt/mmcblk1p3 那条设 enabled='0'，uci commit fstab； 5. reboot，回来后 df -h 验证 /overlay 来源是 /dev/mmcblk1p3、可用 ~53G。 全程每步先确认再执行，复制完成、UUID 对上之前绝不改 fstab。
🔴
高风险：迁移运行中的系统，需人工核对后重启
🔑
UUID 现查不写死（固件重置后会变）
🧹
先清空再复制：mmcblk1p3 可能有旧 extroot 残留，不清会新旧混合
❌
不能进 uci-defaults：这是一次性迁移，不是声明式配置
3sysctl 网络优化 + nikki 调优
帮 R5C 执行优化： 1. 写入 /etc/sysctl.conf 并立即生效（写入前去重防堆叠）：rmem_max/wmem_max=16MB，tcp_rmem/tcp_wmem max=16MB，tcp_mtu_probing=1，nf_conntrack_max=131072，tcp_fastopen=3 2. 若 nikki 已安装，UCI 设置：log_level=error，清理 cron 改 */30 * * * *，清理阈值 5MB，commit 后重启 nikki。 执行完验证所有参数是否生效。
📊
sysctl：rmem/wmem_max=16MB、tcp_rmem/wmem max=16MB、tcp_mtu_probing=1、nf_conntrack_max=131072、tcp_fastopen=3
⚙️
nikki：log_level=error、清理 cron */30 * * * *、清理阈值 5MB
🛡️
nikki 是第三方 feed 包，没装回则后半自动跳过（脚本有 uci -q get nikki.mixin 守卫）
4LuCI 365 天免密登录（cookie + localStorage 双保险）
帮 R5C 实现 LuCI 后台 365 天免密登录，cookie + localStorage 双保险，支持所有主题。 【架构铁律】用独立 uci 键 luci.sauth.cookie_days（默认365）控制 cookie 时长；sessiontime 固定为 604800（7天）绝不设大——设大会让 rpcd 会话堆积、正确密码也间歇性 403。 第一层（cookie，与主题无关）：改 /usr/share/ucode/luci/dispatcher.uc 的 Set-Cookie 行，max-age 用 (+(uci.get('luci','sauth','cookie_days') ?? 365))*86400；并设 cookie_days=365、sessiontime=604800。 第二层（localStorage，覆盖所有主题）：把脚本注入通用 /usr/share/ucode/luci/template/sysauth.ut 和全部 themes/*/sysauth.ut（活动主题决定渲染哪个，OpenWrt 主题会回退通用模板）。脚本逻辑： - 模块级 autoLogging 标记，自动登录期间禁止 save 回写（防旧密码复活）； - submit 事件 + prototype.submit 双拦截存 base64 凭据（365天过期）； - 加载时读 localStorage 未过期则自动填充提交； - fuser（密码错误）时清 localStorage 并"设置"lr_tried 锁死本会话防死循环。 注意：通用模板原生 <input type=submit> 提交不触发 prototype.submit，靠 submit 事件；bootstrap 主题 sysauth.js 程序化 form.submit() 不触发 submit 事件，靠 prototype.submit。 第三层（登录时长字段）：改 /www/luci-static/resources/view/system/password.js，在 admin/system/admin 页加"登录时长（天）"输入框，默认365，读写 luci.sauth.cookie_days（绝不写 sessiontime）。 每改一个模板用 curl -s http://127.0.0.1/cgi-bin/luci/admin/system/admin 验证渲染输出；改完 rm -f /tmp/luci-indexcache*.json && /etc/init.d/uhttpd restart，再让我退出重登测试。
🔴
sessiontime 固定 604800（7天）绝不设大，否则日志记 accepted 但响应 403、rpcd 会话堆积
📅
真正长期免密靠 luci.sauth.cookie_days=365 + localStorage（模板写死 365 天过期）
🎯
OpenWrt 主题回退通用模板（不是 bootstrap）→ 用 curl 抓渲染确认改对了文件
🆘
应急登不进：/etc/init.d/rpcd restart 清积压会话
5把魔改纳入备份（扛过备份 / 恢复）
帮 R5C 把 LuCI 登录魔改纳入备份：往 /etc/sysupgrade.conf 追加这 4 个路径并去重—— /usr/share/ucode/luci/dispatcher.uc /usr/share/ucode/luci/template/sysauth.ut /usr/share/ucode/luci/template/themes/bootstrap/sysauth.ut /www/luci-static/resources/view/system/password.js 然后用 sysupgrade -l 验证这 4 个文件已进备份清单。
✅
默认就在备份：/etc/config/*、/etc/sysctl.conf、密码 / 密钥
❌
需手动加：上面 4 个 /usr/share/ 和 /www/ 魔改文件
⚠️
仅恢复到相同固件版本安全；跨版本应重跑 ④ 而非还原旧文件。全盘重刷时 extroot 数据需重做 ② 的复制步骤
