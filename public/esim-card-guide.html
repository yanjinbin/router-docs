⚠ 炸卡风险说明： 两家都存在写满后炸卡的可能，但属于幸存者偏差，实际概率极低。每张 eUICC 写入不超过 6–8 张 Profile 是安全上限。iOS 新系统已加入写卡边界保护，早期 iPhone 11 炸卡案例较多是历史问题。
ARM Kigen 是什么
为什么它比 ECP 兼容性好
本质：跑在安全芯片上的操作系统
eSIM 实体卡里有一块安全芯片（eUICC），芯片上需要跑一个 OS 来管理 Profile（运营商配置文件）的下载、安装、删除。这个 OS 就是芯片方案的核心。

运营商侧的 SM-DP+ 服务器负责推送 Profile，服务器在对接时会按照某个芯片方案去测试和优化。ARM Kigen 严格遵循 GSMA SGP.02 / SGP.22 国际标准，主流运营商基本都做过 Kigen 的兼容验证，而 ECP 是国内厂商自己的实现，细节偏差导致部分运营商/设备报错或激活失败。

核心结论： 卡激活失败、Profile 下载报错，根源往往不在 App 操作，也不在网络，而在芯片方案这一层——ECP 遇到挑剔的运营商 SM-DP+ 服务器就会翻车，Kigen / G+D 则基本不会有这个问题。

选购策略总结
来自 @realNyarime 奶昔 的建议
决策树
你是安卓用户？
  ├─ 是 → 不碰美国运营商 / 日本 NTT DOCOMO？
  │      ├─ 是 → 小白卡（¥20）搞定
  │      └─ 否 → 运营商有 EID 白名单要求 → G+D（eSTK / BeeSIM）
  └─ 否（iPhone）
        └─ 需要读卡器救砖 → eSTK；不想备读卡器 → BeeSIM
⚠ 写卡上限：每张 eUICC 建议写入不超过 6–8 张 Profile，写满是炸卡的主要原因。iOS 新系统已有写卡边界保护，早期 iPhone 11 炸卡案例是历史问题。
⚠ BeeSIM 老款注意：老款来源于外版 iPhone 双卡改机卡槽，部分有锁，在 T-Mobile / Google Fi / Tello 等运营商会无法写入。购买时确认是新款（G+D 直接制卡）。
💡 保号场景提示：对于需要保留的电话号码（转移麻烦、需去当地门市等），优先选实体 eUICC——换手机时号码不受影响，比内置 eSIM 更灵活。电话号码的寿命往往比一部手机长。
